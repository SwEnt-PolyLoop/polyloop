# Gemini is called through Vertex AI, without an API key

The LLM proposal sends both parties' condition photos to Gemini. We call it through Vertex AI (`@google/genai` with `vertexai: true`, an EU location) with the Cloud Functions service account, instead of the Gemini Developer API with a key in Secret Manager like Geocoding. The Developer API's free tier is not an option: its terms allow only paid services in an app offered to users in Switzerland or the EEA, so either way the calls are paid. Vertex AI then gives the same Gemini models with no key to store or rotate, processing in the EU, billed to the project's existing Blaze account. It needs the Vertex AI API enabled on the project and the `roles/aiplatform.user` role on the Functions service account. Switching to the paid Developer API later is one constructor flag and a secret. Gemini sits behind a provider-neutral interface, so an open model on an OpenAI-compatible endpoint (e.g. at EPFL) can replace it if the credits do not cover Vertex AI.
